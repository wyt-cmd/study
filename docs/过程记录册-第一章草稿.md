## 1.1 需求清单与可测指标

| 编号 | 需求描述 | 可测指标 | 优先级 |
| --- | --- | --- | --- |
| R1 | 题目按分类维护，支持增删改查 | 分类可增改，仅空分类可删；题目按分类、题型、关键字分页查询 | 高 |
| R2 | 题目批量导入，并拦截重复题干 | 1000 条导入耗时 ≤ 30 秒；题干规范化后的哈希与库中或本次文件内重复时不得入库 | 高 |
| R3 | 手工组卷与按规则随机抽题 | 同一试卷内题目不重复；抽出题目分值之和与设定总分偏差为 0，否则拒绝组卷 | 高 |
| R4 | 限时考试与超时处理 | 同一考生同一试卷只能有一条考试记录；到截止时间未交卷记为超时并完成判分；交卷与判分在同一事务内 | 高 |
| R5 | 客观题全对得分、主观题按关键词比例得分 | 分数用整数；部分得分按 `(满分 * 命中数 + 关键词数 / 2) / 关键词数` 四舍五入；得分夹在 0 与满分之间 | 高 |
| R6 | 成绩按试卷聚合、分页、导出 | 1000 条成绩查询响应 ≤ 1 秒；聚合与分页的 SQL 条数不随结果行数线性增长 | 高 |
| R7 | 登录、三角色、接口鉴权、令牌失效 | 未登录 401；角色不足或访问他人答卷 403；退出或停用账号后原令牌不可再用 | 高 |
| R8 | 题图与轮播图上传 | 文件进 MinIO，库中只存访问地址；凭据来自环境变量 | 中 |

R8 不是任务书必做项，是现有代码里已经做的扩展，正式清单里可以保留并标明“扩展”。

## 1.2 技术选型与否决理由

| 选型项 | 候选方案 | 否决理由 | 结论 |
| --- | --- | --- | --- |
| 主控框架 | Spring Boot 3 / 手写 Servlet | 任务书指定 Java 17 与 Spring Boot 3。手写 Servlet 要把参数校验、事务、鉴权和异常响应都铺在入口里，controller 很容易变厚，后面改判分和组卷时不容易把业务留在 service。课程周期只有 20 个工作日，不值得再造一层框架。 | Spring Boot 3 |
| 持久层 | MyBatis-Plus / Spring Data JPA | 成绩聚合要求 SQL 条数保持常数级，并且要能数出来。JPA 的懒加载和级联在分页、导出时容易多打查询，条数不稳定，验收时不好解释。MyBatis-Plus 负责单表，聚合写在 `ExamRecordMapper.xml`，一条语句对应一次查询，便于对照 `X-Sql-Count`。 | MyBatis-Plus |
| 前端方案 | Vue 3 + Element Plus / 服务端模板 | 任务书指定 Vue 3、Element Plus、Vite。考试页要在浏览器里倒计时、本地保存答案并在交卷前整卷提交，用服务端模板每次改答案都刷新页面，限时作答会中断。Element Plus 的表格、上传和对话框够覆盖题库、组卷和成绩，不再引入另一套组件库。 | Vue 3 + Element Plus + Vite |
| 其他 | 整数分 + Redis 会话 / double 分 + 只靠 JWT 过期 | 任务书要求边界分数无浮点误差，且令牌可失效。`double` 做百分比得分会在 0.5 边界附近出现 0.1 尾数，和“偏差为 0”的总分校验也不一致，所以分值全部用 `int`，主观题用整数四舍五入。只靠 JWT 自包含声明无法在退出或停用账号时立刻作废，因此登录时把 jti 写入 Redis，过滤器比对该键，退出或停用时删除。文件不落本地磁盘，因为任务书指定 MinIO，换机器时不丢题图。 | 整数分；Redis 保存可作废的 jti；MinIO 存文件 |

接口文档用 Knife4j（`/doc.html`），与 springdoc 同一套 OpenAPI，不再单独维护一份会过期的 Markdown 接口表。

## 1.3 数据模型与接口

数据表 10 张：`sys_user`、`question_category`、`question`、`paper`、`paper_question`、`paper_rule`、`exam_record`、`exam_answer`、`practice_record`、`banner`。脚本在 `docs/sql/schema.sql`。

关系：用户 1—n 试卷（`creator_id`）和 1—n 考试记录；分类 1—n 题目，题目用 `stem_hash` 唯一；试卷 1—n 试卷题目，并 1—n 抽题规则；考试记录 1—n 作答明细，且 `(user_id, paper_id)` 唯一，用来挡住重复开考。分数列都是 `INT`。

接口按 10 组、约 47 个方法，前缀 `/api`：

| 分组 | 方法 |
| --- | --- |
| 认证 | 登录、退出、当前用户 |
| 用户 | 分页、新增、修改、启用/停用 |
| 分类 | 树、列表、新增、修改、删除 |
| 题目 | 分页、详情、热门缓存、增改删、导入模板、导入预检、导入、AI 草稿 |
| 试卷 | 列表、可考列表、详情、手工组卷、智能组卷、改状态、删除 |
| 考试 | 开考、取卷、保存答案、交卷 |
| 刷题 | 下一题、提交、小结（扩展） |
| 统计 | 我的成绩、成绩分页、聚合、排名、导出 |
| 文件 | 上传、读取 |
| 轮播 | 前台启用列表、管理端增删改查（扩展） |

业务判断放在 service。抽题不重复和总分校验在 `PaperPicker`，客观题与关键词评分在 `ScoreRules`，这两处有单元测试。
